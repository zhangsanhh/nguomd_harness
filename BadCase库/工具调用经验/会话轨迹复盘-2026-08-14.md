## 二、问题清单（按价值排序）

### 问题 1：会话日志「每轮追加」机制 = 高频重复 edit（5/5 会话命中）
- 证据：5 个会话全部对 `会话日志与摘要/2026-08-14/会话摘要.md` 重复 edit 3-8 次；21ace44c 对修改清单 edit 5 次；352d923e 一次 edit 失败（old_string not found）后 read 重试。
- 根因：AGENTS §四.1「每轮回复前先记本次问答」→ 长会话每轮 read+edit 同一长文件；文件越长 old_string 越长；多会话同日并发写还会互相冲突触发重试。
- 修复：改为批量追加——每会话结束（或每 5 轮）一次性写入，用 bash `cat >>` 追加（无 old_string 匹配问题）；摘要文本先在会话内攒齐。
- 预期收益：每个长会话省 5-10 次工具调用。

### 问题 2：DSH 路径/结构未沉淀，跨会话反复从零探索（4/5 会话命中）
- 证据：f41a8cfc 有 8+ 次对 `node_modules/@deepseek-ai/` 的 cd/ls 探索（连续重复调用清单几乎全是它）；38a43aca、352d923e 均踩 `~/.dsh/profiles/web/node_modules/` 不存在（exit 1 后再换路径）；95d65cd7 多轮 grep/sed 挖 DSH 源码。
- 根因：「最小背诵集」（CBDD.3）没有 DSH 侧落地——目录结构、配置分层、已知坑位每次会话重新摸。
- 修复：在 `00_系统配置/dsh/` 建 `DSH速查.md`（路径树、配置分层、常用命令、坑位清单），AGENTS 加指针行。
- 预期收益：探索类会话省 30-50% 工具调用。

### 问题 3：内联分析脚本反复重写，无跨会话复用（3/5 会话命中）
- 证据：95d65cd7 同一段 node 解压/统计脚本重写 3-4 次（每次微调）、zstd 解压脚本 3 次；f41a8cfc 同一 yaml 解析脚本 2 次、同一 find 全盘扫描 2 次（20K+10K 输出）、同一 for 循环读源码 2 次。
- 根因：分析脚本用完即弃；「少调用」规则只管单会话内，跨会话复用无载体。
- 修复：常用分析脚本沉淀 `00_系统配置/dsh/scripts/`（如 session 解压统计脚本），AGENTS 加「脚本先查后用」。
- 预期收益：分析类任务每次省 2-4 次脚本重写。

### 问题 4：bash 大输出与敏感文件读取（安全 + token 双重问题）
- 证据：95d65cd7 执行 读取凭据文件（**触碰密钥边界**，且回传 49K 字符）；同会话 awk 输出 49K；f41a8cfc find 全盘扫描 20K+10K、yaml dump 14K×2。
- 根因：AGENTS §二.5 已规定「读写密钥需同意」，但表述在「读取」场景不够硬（模型仍直接 cat）；bash 输出无闸门。
- 修复：① 安全条款改为「禁止读取密钥/Token 文件内容，确需时先询问」；② AGENTS 加「bash 输出闸门」：大目录 ls/find 必须 `| head`、禁止无界 cat 大文件；③ 沉淀 BadCase 案例。
- 预期收益：每会话省 30-100K 字符回传，堵住密钥泄露风险。

### 问题 5：单一主题无限搜索（搜索预算缺失）
- 证据：352d923e 的 31 次 web_search 中 **23 次围绕「re-image」**（74%），反复验证一个查无实据的功能，最终才确认不存在。
- 根因：无搜索预算概念；实体消歧（XQYT.1）未执行——用户不确定的指称应先确认存在性，而非连搜 23 次。
- 修复：AGENTS 加「搜索预算」：同一主题 3 搜无权威实据 → 停止并告知「查无实据」，或 ask_user 确认目标再搜。
- 预期收益：此类会话省 ~20 次搜索。

### 问题 6：规则文件会话内反复改写 + 连带同步放大调用
- 证据：95d65cd7 对 `~/.dsh/AGENTS.md` 与项目 AGENTS.md 各 write 3 次；21ace44c 对 AGENTS.md/README/BadCase README 反复 edit；「变更同步检查」导致改一处连带 2-4 次 edit。
- 根因：规则边做边改、一次性不到位；同步检查（§二.11）无预清单。
- 修复：规则变更集中批次化（一次会话改完所有连带文件）；同步文件预列清单，减少回读。
- 预期收益：规则变更类会话省 30-40% 调用。

## 四、剩余风险

- 复盘基于 8-13 至 8-14 的 20 个会话（部署首两日），样本量有限；机制性结论（日志/路径/脚本）已多会话交叉验证，可信度高；单会话偶发问题（如 re-image）按案例处理。
- token 折算未按缓存折扣精算，节约估算为调用次数口径，实际账单节省比例取决于缓存计费规则。
- 会话摘要文件同日多会话并发追加是日志机制冲突主因，批量追加方案需实测多会话并发场景。
