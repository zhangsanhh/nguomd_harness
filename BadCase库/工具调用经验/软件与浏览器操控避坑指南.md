# 软件与浏览器操控避坑指南（2026-08）

> 定位：本工作区的「操纵电脑」核心专项——控制浏览器里的页面、控制本机各种软件（GUI 自动化）。与《信息爬取经验与避坑指南》（内容采集专项）互补：本文档管「怎么把软件和浏览器操起来、点到位、不误伤」，爬取指南管「数据怎么取全、取干净」。
> 来源：2026-08-01 至 08-12 会话日志与 Pitfall 经验库的真实操作复盘；命令均实测过。
> 用法：操控前读第三节清单；失败后按第二节/第四节索引命中编号，回库读细节。

## 一、总原则

1. **先选通道，再动手**：三层通道按可靠性排序——网页：页面内 fetch（登录态自动带签名）＞ CDP 驱动 DOM/Network ＞ GUI 点击；桌面软件：App 自身接口/配置文件 ＞ AX/JXA 辅助功能 ＞ 合成点击。优先选「最不容易坏的一层」，GUI 点击是最后手段。
2. **每步状态断言**：操作前拿引用/快照 → 操作 → 重新取状态断言（URL、元素存在性、文本变化、网络请求、日志）。ref 是瞬时的，重拍后必须重新取，不重试旧 ref。
3. **环境三查**：桌面是否解锁、目标进程是否健康、权限（TCC 辅助功能/麦克风、CDP 开关）是否已授权。
4. **安全三不**：不碰用户主浏览器（用专用 profile）；不抢用户正在操作的界面；杀进程按端口/命令行特征精准命中，不整应用乱杀。
5. **熔断**：同一操作连续失败 2-3 次即停手，输出当前页面/窗口状态交用户，不无限循环。

## 二、浏览器操控（页面级）

### 2.1 登录态与专用浏览器

- 专用 Chrome 启动（用 `open`，进程才能存活；nohup 直接起会被杀）：

```bash
open -n -a "/Applications/Google Chrome.app" --args \
  --remote-debugging-port=9223 \
  --user-data-dir=$HOME/.codex/zhihu_cdp_profile \
  --no-first-run --no-default-browser-check \
  "https://www.zhihu.com/"
```

- profile 必须放持久路径（`~/.codex/zhihu_cdp_profile`）；放 /tmp 会被系统清理导致登录态丢失。登录一次，后续任务直接复用，**收尾只杀进程、不删 profile**。
- 关闭专用浏览器按端口特征杀：`pkill -f "remote-debugging-port=9223"`；**不要用 osascript 退出 Chrome**，会连用户主浏览器一起关。
- 连接前确认工具是否注入：官方浏览器控制依赖 `mcp__node_repl__js` 工具，MCP 开启后未必立即出现在当前会话；没有就手动桥接 node_repl（详见爬取指南 3.2，需 `_meta` 传 turn metadata）。
- 专用实例必须带 `--user-data-dir`：Chrome 136+ 稳定版禁默认 profile 远程调试（实测 151）——不带则进程正常但端口不监听（日志 requires a non-default data directory）。
- 直连「日常已登录 Chrome」用 AppleScript（零重启、登录态全在）：`tell application "Google Chrome"` 的 set URL / get title / `execute front window's active tab javascript`，可导航、读 DOM、JS 触发点按；无截图与网络层。敏感动作（读 cookie/发布/删除）先报方案。

### 2.2 页面内 fetch（首选数据通道）

- 页面刚加载的头几秒 fetch 可能缺签名返回 403（知乎 code 10003），**先轮询接口就绪**：`/api/v4/questions/{id}/answers?limit=1&offset=0` 返回 200 再开始拉取（爬取指南 2.6）。
- 跨域 fetch 被 CORS 拦（如 www.zhihu.com 里 fetch zhuanlan.zhihu.com）：**把标签页导航过去再取 DOM / js-initialData**，不在原页面硬试。
- 大 JSON 别走剪贴板（Cmd+A/Cmd+C + pbpaste 会复制不全），用页面内 fetch 一次 `returnByValue` 返回，实测 37MB 级原始数据无截断。
- 抓取环境必须干净 profile；「沉浸式翻译」等扩展会把 JSON 字段名翻译成中文，直接破坏数据。

### 2.3 渲染与页面数据

- 需要 JS 渲染的页面用 CDP 常驻实例（`--remote-debugging-port` + Node WebSocket），**不要用 `--headless --dump-dom`**（实测挂起超 90 秒）。
- 程序化抓官方数据：**先解析页面 data 属性拿真实帧/URL**，不凭模式拼时间。中央气象台雷达图 URL 内嵌的是 UTC 时间，按北京时间拼会全部 404（Pitfall-064）。
- 分页可能返回超量/重叠页（limit=20 返回过 39 条），**按 id 去重后再统计**；列表正文可能截断，先看 `content_need_truncated` 标记，为 true 才逐条拉全文。
- 结构化数据优先 Network 截获（抖音 detail 接口，页面 JS 自动带签名），比解析 DOM 稳。

### 2.4 浏览器自动化基线（必做）

1. 操作前 snapshot 拿 ref（agent-browser）或 DOM 引用（CDP），先有引用再操作，不盲点。
2. 操作后必须重新 snapshot 断言：URL、元素存在、文本变化。
3. 点击被遮挡（弹窗/横幅/其他窗口）→ 先处理覆盖元素 → 重新 snapshot → 按语义定位重试，**不重试旧 ref**。
4. 重试纪律：失败先看错误，修正后重试 1 次；仍失败换路；连续 2-3 次熔断交用户。

## 三、本机软件操控（GUI 自动化）

### 3.1 通道选择（按可靠性）

| 目标                            | 首选                                      | 备选                 | 已验证教训                                                                       |
| ------------------------------- | ----------------------------------------- | -------------------- | -------------------------------------------------------------------------------- |
| Codex 桌面侧栏/面板             | JXA 递归遍历＋位置过滤                    | AppleScript 全量快照 | AppleScript`entire contents` 快照不可靠，曾误判「主会话被关闭」（Pitfall-041） |
| Flutter 应用（FlClash）         | 设 AXEnhancedUserInterface=true + AXPress | CGEvent 合成点击     | 合成点击被窗口遮挡时常无效；Flutter 语义树默认不完整（Pitfall-061）              |
| Chrome 标签/窗口                | 窗口级 + System Events AXMain 判前台      | Chrome 字典 tab 属性 | tab.URL()/active()/pinned() 全不可用，仅 title() 可读（Pitfall-045）             |
| 应用内数据操作（Typeless 词典） | 走 App 自身 UI/接口                       | CDP Fetch 改写请求   | Fetch.continueRequest 的 url 改写静默无效，请求仍按原 URL 发出（Pitfall-046）    |

### 3.2 权限与授权（最容易静默失败的层）

- **launchd 里的 osascript 被 TCC 静默拒绝**：手动跑正常、定时跑全 FAIL，且 RC=0、stderr 为空。授权对象是任务负责进程（实测为 /bin/bash），授权后用 `launchctl kickstart -k gui/$(id -u)/<label>` 即时复测（Pitfall-029）。
- **临时重签名 = 换应用身份**：Typeless 改包后 TCC 授权全部失效，出现旧 patched 条目；`tccutil reset Microphone/Accessibility <bundle-id>` 后重新授权（Pitfall-037）。
- **CLI 调隐私框架直接崩溃**：无 App Bundle 与 usage description 时调语音识别，进程 `__TCC_CRASHING_DUE_TO_PRIVACY_VIOLATION__` 终止，不是语法问题（Pitfall-028）。
- **锁屏 = Computer Use 失效**：锁屏期间服务启动会 SIGABRT 崩溃；自动化前必须确认桌面解锁，崩溃后需在设置 toggle 或重启应用（爬取指南 3.3）。
- **桌面 App 的 UI 开关不可全信**：MCP「启用」开关写配置失败被静默吞掉，重启后回退；持久化以 `~/.codex/config.toml` 落盘为准（Pitfall-022）。
- CDP 开发者权限默认关闭、属高风险调试权限，按需开启，不常开（8/8 日志）。

### 3.3 点击与输入

- 合成点击（CGEvent）受前台窗口遮挡/焦点影响：先查 `CGWindowList` 确认目标窗口在顶层，窗口被覆盖时先用 AX 移动到未遮挡位置，操作完还原（Pitfall-061）。
- Flutter 应用：设 `AXEnhancedUserInterface=true`，**每次动作前重新取完整树**；按钮/复选框/节点行用 AXPress；文本输入＝点击字段 + System Events Cmd+A + Delete + keystroke。
- 按键语法是 `super+t`（Cmd+T），不是 `Meta+t`。
- 用户正在操作界面时不要硬抢：报「The user changed ... app」先重新 `get_app_state` 再继续（爬取指南 3.3）。
- 应用标识有歧义时用显示名（`Google Chrome`），不用 bundle id。

### 3.4 状态读取与判定（防「看着在工作，实际没生效」）

- **窗口 AX 标题不可靠**：ChatGPT 桌面窗口标题固定为「ChatGPT」，线程名不进标题，按窗口标题匹配线程的脚本会永久空转（Pitfall-043）。
- **updated_at 是创建时间不是活动时间**：session_index.jsonl 的 updated_at 不随消息刷新；判活跃用 `~/.codex/sessions/**/*.jsonl` 最新 mtime（Pitfall-043）。
- **闲置判定必须与进程生命周期对齐**：起点取 max(会话最后写入, 进程启动时间, 最近前台查看)；否则 App 重启后按旧 mtime 立即被误杀（Pitfall-051）。
- **每轮处理数为 0 ≠ 任务生效**：监控脚本要加空转计数/告警，日志无 FAIL 不能证明执行成功（Pitfall-043/029/042）。
- 读不到状态不要立刻判定「窗口关了/功能没了」，先换遍历方式复核（JXA vs AppleScript 对拍）（Pitfall-041）。

### 3.5 应用生命周期与防误杀

- 启动应用用 `open -a` / `open -n -a ... --args`（后台进程才能存活）。
- 杀进程按端口/命令行特征精准命中（`pkill -f "remote-debugging-port=9223"`），不整应用退出；专用浏览器收尾只杀进程、保留 profile。
- 闲置/清理类自动化默认 dry-run；可覆盖变量统一 `${VAR:-默认}`，**先核对测试目标真的被日志采用，再跑真实副作用路径**（曾因测试参数未生效误退生产应用，Pitfall-044）。
- `ps | grep -F "$PATH"` 会自匹配（父 shell argv 含路径），进程存在性检查用掩码正则 `[/]path` 并在 launchd 干净 argv 下验证（Pitfall-044）。
- 定时清理类任务（Typeless/有道翻译）：退出进程 → 清缓存 → 重启；验证以「进程树消失 + 缓存目录清空」为准（8/10、8/11 日志）。
- 排查「某应用隔天被自动关」：先查本地 LaunchAgent 闲置退出日志（`~/.codex/idle-window-closer.log`、`idle-chrome-closer.log`），再查配置回退；**本地自装自动化是第一嫌疑**，不是浏览器缓存机制（Pitfall-054）。

### 3.6 软件内数据操作

- Electron CDP 改写请求（Fetch.continueRequest 改 url/method）静默无效，只对重定向请求生效；批量操作优先驱动 App 自身 UI/接口（Pitfall-046）。
- UI 里「悬停才渲染」的按钮（Typeless 词卡删除）：向根节点派发 `mouseover`(bubbles)+`mouseenter` 触发 React 渲染，再 `.click()`；筛选 tab 会改变结果集，先切「所有」再搜（Pitfall-046）。
- 批量删除/写入以网络响应体为准（`{"status":"OK",...}`），不要用 `/true/` 判断（Pitfall-046）。
- 双击文件提示「无权限」不一定是权限问题：OneDrive 占位文件（dataless）打开失败多为代理 TLS 中断，先查 `ls -lO` 标志与 `curl --noproxy` 对比（Pitfall-030）。

## 四、软件操控专用检查清单（每次操控前）

1. **通道**：网页 → 页面内 fetch / CDP？桌面 → AX/JXA / 接口？选最不容易坏的一层，GUI 点击放最后。
2. **环境**：桌面解锁？目标进程在跑？TCC/辅助功能/CDP 已授权？launchd 场景 PATH 对吗？
3. **隔离**：会不会碰用户主浏览器或正在用的窗口？要不要专用 profile / 独立实例？
4. **安全**：dry-run 开了吗？杀进程特征精准吗？改动前备份了吗？可覆盖变量真的生效吗？
5. **断言**：操作后拿什么证据确认成功（URL、元素、日志、网络请求、流量）？
6. **熔断**：连续 2-3 次失败就停手，输出当前状态交用户。
