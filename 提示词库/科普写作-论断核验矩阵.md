# 科普写作：论断核验矩阵（来源清单 → 句子级可回溯）

> 定位：为「100+ 可核验来源」补最后一层——正文每个高影响论断可回溯到具体来源、定位、独立性与置信度。只做操作层，总原则以 AGENTS.md §3.1 为准；按需启用，不写入 AGENTS.md 以省 token。
> 创建：2026-08-03 ｜ 适用：科普长文、深度研究、结论型写作；简单问答与纯信息整理不套用。

## 一、启用条件（命中任一即可）

- 交付物含 ≥10 个事实性论断，或用户要求「来源可核验／100+ 来源」；
- 选题时效性强（AI、政策、工具评测），结论可能过时或被推翻；
- 用户要求证据级交付（逐条引用、对比、决策建议）。

## 二、流程六步

1. **论断清单**：正文定稿前，把关键论断拆成 C001、C002…，每条一句、可证伪。只列高影响论断（结论、数据、因果、推荐）；常识与过渡句不列，控制矩阵规模。
2. **证据挂链**：每个论断挂来源 ID——有附录编号直接复用附录编号（S001…），新增来源用 N001…，不再另建编号。每条证据必记：来源标题与发布方、URL/路径、定位（章节/页/行/表格）、日期或版本、来源类型（官方一手/论文/媒体/转载/仓库）。只记录真正打开过的来源，不记搜索摘要。
3. **反证检索（固定阶段，未命中不算完成）**：合成正文前专跑一轮反向检索：批评、失败案例、负面复制、过时/废弃行为、竞争解释、数据反例。结论分四档：未检（未执行）；已检索未命中（搜了无实质反证，论断成立）；命中-缓解（有反证但只限缩论断，补一句限定即可）；命中-反驳（反证与论断冲突，必须改写或降级并标 contested）。
4. **独立性判定**：同一项目 README 与其官网、转载与被转载页、同一机构多页面＝同一来源家族，不构成交叉验证；跨家族来源才可互证（与 AGENTS.md §3.1.6 一致）。
5. **内部一致性检查（三查）**：每条论断做数字/枚举一致性（计数与列表项数、比例与分子分母）、术语前后一致（同一概念是否换名或混用）、结论与前提是否互斥；逐条给出结论（通过/命中），命中先改正文再继续，并把结果记入矩阵（如「contested（内部矛盾）」）。
6. **填矩阵＋自检**：按下表填写。定稿前逐行核对：高影响论断满足「1 条强主源＋1 条跨家族独立佐证」或有显式不确定性标签；正文锚点/独立性/反证/内部一致性/置信度列空白即视为未完成。

## 五、标签规则

1. 高影响论断默认标准：1 条强主源＋1 条跨家族独立佐证；达不到则显式打标签（single-source/likely/contested/weak/stale/unknown），不得静默放行。
2. 标签是交付物的一部分；缺失或弱证据必须标注，不许藏。
3. 矛盾与不确定性单列一节，每个矛盾给出两边证据 ID。
4. 衔接：证据权重/来源审查按 AGENTS.md §3.1；反证逻辑层检查可用某资料存档中的「反证法/对手角色」章节；本文件只管落盘结构与流程纪律。

## 六、验收标准

- 附录保留原「来源清单」（数量不变），矩阵/证据表新增为核验资产；
- 每条高影响论断可回溯：论断→证据 ID→来源＋定位，链路无断点；
- 正文锚点列已填且可直接回查原文；
- 反证检索按四档给出结论，内部一致性逐条给出结论（通过/命中），均可见于矩阵；
- 矩阵无空白关键列；正文表述与矩阵标签一致（如正文写「共识」，矩阵不得只有 single-source）。
