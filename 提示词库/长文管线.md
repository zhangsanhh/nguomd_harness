# 长文管线（GJZX-005）：长文档分层消费

> 定位：超长文档/长内容任务（一次灌不进上下文、质量看运气）的专项处理管线。一般复杂任务先遵循项目 `AGENTS.md` §6.2 的渐进式处理披露；用户主动开启计划模式时以计划模式为准。本文件对应人机协作迭代史（重构版）GJZX-005。
> 触发：文档超长（约 >1 万汉字或超过单次上下文舒适区）、多章节结构、来源需核验的写作/整理任务。
> 建立：2026-08-14（北京时间）

## 管线六步

1. **清洗**：修正错字、口语乱句、无意义段落；提取正文结构（标题层级/章节/要点），去噪。
2. **对齐**：先按 L0–L3 意图闸门判定；涉及 L2/L3 时与用户确认目标、范围、格式、约束、验收标准（需求澄清纪律五维，见 `提示词库/需求澄清纪律.md`）；超长任务先报骨架再动笔。
3. **骨架确认**：产出章节骨架（标题＋每节要点＋预计篇幅），用户确认后再写正文——不直接交付全文。
4. **来源核验**：每个高影响论断按证据文化核验（信息分层、来源权重、反证检索、缺口即停，见全局 AGENTS §三）；长文引用来源 ID 附录编号。
5. **独立审查**：高风险/科普/不可回退内容走独立审查（skill independent-review，只审不写）；连续三次不过熔断转人工终审。
6. **交付验证**：对照验收标准逐项检查（长度、结构、论断可回溯、格式）；未达标修订最多两轮再转人工。

## 配套机制

- 长文档分块读取：按标题切片，逐块消费后合并，避免一次读满上下文；工具结果超长时用 head/tail 截断阅读。
- 超长原始素材先落盘（raw_data 或工作区对应目录），不贴全文进对话。
- 交付物必须可核验：来源列表、论断标签、验证记录随文附上；无法验证的标「待验证」，禁止空话。

## 返工减返增量（R-01/R-02/R-04/R-06）

1. **启动契约**：动笔前内部填写目标对象、目标日期/版本、材料范围、交付位置、验收标准和明确排除项；关键缺口才提问。
2. **覆盖账本**：长材料或多源材料先登记材料类型、预期总量、已读量、阻断项、排除项、重复项、未读清单和代表样本。覆盖项与缺口均已登记，才能使用“全量完成”；否则写“阶段完成”或“证据不足”。
3. **增量整体回归**：任何补写、升版或替换都要重新检查全文结构、重复结论、独特信息、日期/版本、链接、派生产物数量和状态用词；只检查新增段落不算通过。
4. **就近复用**：开始前只检索最相关的 1—3 条 Bad Case 或 Pitfall，把教训改成当前任务的检查项；完成后记录是否命中、是否复发，不整库加载。

这四项是执行控制，不要求另建数据库；覆盖账本、映射和回归结果可写入任务已有的 README、摘要或交付报告。

## 验收

- 交付不依赖单次会话状态：压缩/断点后续接时，骨架与来源记录仍可独立消费。
- 失败率被流程压住：任一环节出问题可定位到具体步骤，沉淀入 BadCase库。
