# 资料参照检索规则（通用触发器 · Agentic RAG）

> 版本 v2.4｜2026-09-11 用户批准并定性为 Agentic RAG｜规则本体；全局 AGENTS §二.17 只放指针。
> 定位：问答环节的「检索—引用层」。与日记侧写（`日记处理提示词.md` 第九节）共用硬盘检索口径，差别在触发方式、输入与输出。
> v2 相对 v1：把固定检索流程改为**自主检索循环**（判定 → 查询 → 评估 → 改写重查 → 停止），并明确停止条件与轮次上限。
> v2.1 相对 v2（2026-09-11 用户要求）：来源标注由「独立章节／表格」改为正文内轻量标注；路径与行号默认不写，用户追问才给。
> v2.2 相对 v2.1（2026-09-11 用户要求）：来源**默认完全不标注**（用户凭原句回查，用户主动问时才给完整出处）；同时新增强制语体条款——像正常回答问题那样直接讲，禁止"资料／材料／检索／轨迹／RAG"这类元话语，禁止多方引述式对账与辩论会口吻。检索与核对仍是硬要求，只是不外显。
> v2.3 相对 v2.2（2026-09-11 用户要求）：**参照源不再只有硬盘**。新增 §5.5——硬盘资料是主参照而非唯一依据；关键信息缺口、时效性内容、硬科学机制与需要外部权威的论证，必须用联网检索或既有知识补足，做到论证闭合；同时禁止用模型常识冒充资料主张、也不许拿"资料没有"当留白借口。该口径同样适用于日记侧写与一般交互。
> v2.4 相对 v2.3（2026-09-11 用户要求）：新增 §5.3——**交互问答默认只在前台回答，不落文件**；只有用户明确要求"写成文件／存到某处"时才产出文档，字数类要求在前台遵守即可。

## 一、触发条件

命中任一即执行；均不命中走普通回答，不做检索。

1. **显式指令**：用户说「查硬盘／参照硬盘／硬盘里怎么说／按资料回答」等。
2. **语义命中**：提问落在下列主题域——
   - 人际与沟通：关系、博弈、沟通、谈判、心理与家庭议题
   - 认知与判断：认知、思维、归因、信息茧房、决策、注意力、情绪
   - 成长与方法：学习方法、习惯、自律、时间管理、精力、健康养生
   - 职业与表达：职场、面试、表达、写作、产品、求职
   - 生活议题：金钱、消费、独处、意义
3. **不触发**：纯操作与配置（文件、命令、DSH／Codex 设置）、当天事务与日程、时效型事实（新闻、价格、政策、版本号）、本机流程与台账问题。
4. **触发≠必须检索**：命中后先判断「这个问题真的需要外部资料吗」。提问属于我的通用能力范围、或只需操作本机文件时，直接回答并一句说明未检索的理由。

## 二、参照源

1. 先检测挂载：`ls /Volumes/Elements`。
2. **已挂载** → 硬盘为主参照，电脑侧仅作补充；两者说法冲突时以硬盘为准，用一句自然的话说明分歧与条件差异，不逐方引述。
3. **未挂载** → 电脑为主参照，按主题检索本机可用资料，**不设目录白名单**；这种情况在「没读到」说明里点明是电脑侧资料。

## 三、检索范围与顺序

硬盘为主时：

1. 硬盘内 Markdown 直读（无需转换）：本地资料库各主题目录下的 `.md`。
2. 转换层兜底：DSC `raw_data/硬盘资料文本/`（docx／pdf 机械转换，未校对）。
3. 转换层边界（2026-09-11 用户决定不装 OCR）：docx 来源全部可读；PDF 共 204 个，89 个可用、115 个无文字层（z-library／读秀扫描版），名单见 `raw_data/硬盘资料文本/不可读清单.md`。命中不可读名单、或只在硬盘上见到文件名而读不到正文的，**记为「未读取」**，不得据书名推断内容，也不得写成「没有相关观点」。
4. 引用前回硬盘原件核对关键句。
5. 不纳入：影音、图片、剪映工程、系统目录、回收站。

电脑为主时：按主题依次检索 DSC `raw_data/`、`01_内容整理/`、`02_科普指南/`、`03_生活记录/`、`会话日志与摘要/`、`05_电脑行为日志/`，以及用户指定或其他明显相关的本机资料。不读 私人记录目录，不读密码、密钥、Token。

## 四、自主检索循环（Agentic 部分）

每一轮走完四步，再决定是否进入下一轮。

1. **生成查询**：把问题扩成 2—4 组主题与同义词，选择检索工具（本机用 `grep`／`glob`／`read`；仅在用户要求或题目时效强时用 `web_search`／`web_fetch`）。不把「找这句话本身」当检索目标。
2. **执行并精读**：只精读直接相关段落，必要时读前后文；不做全库通读。
3. **评估证据**：逐项自问——是否答到问题上？来源是否 ≥2 个独立来源？是否存在互相冲突？材料性质是否可信（原创／整理稿／AI 解读）？
4. **决策**：证据充分 → 进入回答；不充分 → **改写查询**（换同义词、换来源目录、上提或下切抽象层级）再查一轮。

**停止条件**（满足任一即停，不无限检索）：

- 已有 ≥2 个独立来源支持同一结论；
- 连续 2 轮无新命中；
- 累计 3 轮已达上限，此时如实写「未检索充分」。

## 五、回答的引用与语体（本规则唯一产物）

本规则只管两件事：**一、来源写不写；二、话怎么写。**

### 5.1 来源：默认不标注（2026-09-11 用户要求）

1. **默认零标注**：回答与产物里不出现来源名、系列名、材料性质、路径、行号、条目日期，也不出现「据某资料／某系列说」这类指引。
2. **不标注不等于无依据**：凡实质主张都经过本轮实际检索与精读，只是不把出处写出来；不得因此放松核对，也不得借"不标注"掩盖未检索。检索与核对仍是硬要求，落点只在会话过程里。
3. **回查机制**：用户会拿回答里的原句回来问出处，届时按 §5.3 提供。因此引用关键句时保持原句可辨识，不改写成面目全非的转述。
4. **用户主动要时再给**：用户问「这句哪来的／哪个资料／哪一段」时，直接给——来源路径｜位置（行号或条目日期）｜性质（作者原创归档／结构化整理稿／正文重写校正版／AI 解读／他人转述），以及检索经过。
5. **性质风险提示**：只有材料性质会影响可信度时才提一句（例如某说法来自 AI 解读而非作者原文），提示后就事论事，不展开来源说明。
6. 同源副本（md 与 docx、结构化分类版与原文）不算独立印证，内部核对时不得当成两个来源。

### 5.2 语体：像正常回答问题，不露检索痕迹（2026-09-11 用户要求）

1. **直接讲观点、机制、条件与做法**，不写"资料显示／作者指出／同篇提到／原文说／这一篇认为"这类元话语开头。
2. **禁止出现检索与 RAG 术语**：资料、材料、来源、检索、轮数、轨迹、Agent、RAG、结构化整理稿、台账等词，不进正文。
3. **不做多方引述式对账**：不写"某某说什么、另一个资料怎么说、我如何评判"。观点直接以陈述句给出，有分歧时用一句自然的话说明分歧点与条件差异即可，不逐方引述。
4. **不做辩论会／文献综述口吻**：不写"有人认为……也有人认为……"的排比对照，不写"这一点在 X 与 Y 中都能看到"。
5. **结构按问题本身的逻辑组织**（机制 → 条件 → 做法 → 边界），不按材料清单组织。
6. **不贴检索说明**：结尾不写检索轮数、查询词、停止原因或范围清单。
7. 只有 §5.1 第 5 条那个例外：材料性质影响可信度时，用一句自然的话点明。

### 5.3 输出形式：默认只在前台说，不落文件（2026-09-11 用户要求）

1. **默认前台**：交互问答一律直接在对话里回答。不生成 Markdown、不写产物、不建索引、不做"整理成文档"的动作，也不主动问要不要存档。
2. **只有用户明确要求才落文件**：用户说"写成文件／输出成 md／存到某处／给我一份文档"时，才按指定位置与格式写（未指定位置则先问一句）。
3. **文件请求的三件套照旧**：落文件后才需要报告路径、字数与验证情况；只在前台回答时不报字数、不报文件。
4. **字数类要求在前台也要遵守**：用户给了字数区间，就在前台把篇幅控在那个区间，不必为此建文件。
5. **例外仅一处**：`日记处理提示词.md` 的日记侧写本身是文件产物，按该规则的路径写入，不受本条影响。

### 5.4 其余判定

1. 未查到相关说法时，用一句自然的话说"这次没找到相关的说法"，不列检索范围清单，不编造，不用模型记忆冒充检索结果。
2. 硬盘未挂载或材料未转换：写「没读到（原因）」，不写成「没有相关观点」。
3. **不生成检索台账文件**，检索过程不留档（2026-09-11 用户选择）。
4. 前台回答、写入文件的产物、派生产物（HTML／索引）三处同一口径：一律不带来源信息；用户问到时只写在当轮回答里，不回头加工已交付文件。
5. **本规则对日记侧写同样适用**：侧写里的资料部分按 §5.2 的语体写，不因"归档"而恢复来源标注。

### 5.5 参照源不止硬盘：缺口必须补足（2026-09-11 用户要求）

**总原则：硬盘是主参照，不是唯一依据。** 参照的优先级是"能不能把问题讲清楚、讲准"，不是"能不能只用硬盘"。为了不跳出论证，允许并鼓励补足。

1. **三级来源**：① 硬盘资料（主参照，优先取用，其观点与分寸优先保留）；② 联网检索（用于时效性内容、需要权威出处的数据与结论、硬盘未覆盖的机制与文献）；③ 既有知识（用于基础原理、常识性框架、过渡推理，以及把硬盘观点接成完整逻辑链）。
2. **必须补足的四种情况**：硬盘只给结论而无机制或出处，而回答又要用到该机制；涉及数据、研究结论、医学或神经科学等硬事实；涉及会变化的信息（政策、价格、版本、行业现状）；硬盘材料明显不足或相互冲突，导致论证无法闭合。
3. **不得跳脱**：论证链上任何一环缺依据时，要么补足，要么降级表述（写成"一种常见解释是……"，而不是定论），要么明确说"这一点没有可靠依据"。**禁止把硬盘里的一句结论直接扩写成看似严谨的机制描述，也禁止用模型常识冒充硬盘主张。**
4. **不反向偷懒**：不许拿"硬盘里没有"当留白借口，也不许因为用了联网或既有知识而省略应该做的硬盘检索。
5. **来源仍不外显**（§5.1 不变）：补足来的内容不单独标注来源，通篇按 §5.2 的语体写；只有材料性质影响可信度、或用户主动问出处时，才用一句话点明性质或给出处。
6. **冲突处理**：硬盘与外部证据冲突时，以证据强度更高者为准（官方一手／学术文献／权威机构优先），并用一句自然的话说明分歧与条件差异，不逐方引述。
7. **适用范围**：本节的补足义务对交互问答、日记侧写、一般问题回答一律适用；不同场景只是"硬盘检索的深度"不同，不是"能不能只用硬盘"不同。

## 六、边界

1. 引用保留推理链，不改写成丢失原意的转述（用户要凭原句回查）。
2. 与日记侧写同一轮并行时共用本规则口径，语体与来源一律按 §5.1／§5.2；侧写的「材料覆盖与缺口」一节仍按 `日记处理提示词.md` §9.4 保留（它是内部核对项，不进前台）。
3. 不新增定时任务、不做后台自动执行；DSH 无提问期钩子，「触发」指按本规则当场执行检索循环。
4. 检索循环受全局成本闸门约束：不为凑来源反复换词，不为验证单一说法无限扩展；但 §5.4 的**补足义务优先于省调用**——论证链缺环时该联网就联网，该承认没依据就承认，不得为了少调用而留缺口。
