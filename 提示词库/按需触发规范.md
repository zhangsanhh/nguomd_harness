# 按需触发规范：需求挖掘 & 逻辑关联词语料库

> 定位：低频专项技能，不写入 AGENTS.md；通用复杂任务的渐进式处理披露已固化在项目 `AGENTS.md` §6.2，本文件只保留按需触发的需求挖掘、逻辑表达和文本写作专项规则。
> 使用原则：未触发不读取、不执行，节省上下文与 token。

## 模块一：需求挖掘协议

### 触发条件（满足其一才启用）

1. 用户明确要求「挖掘一下我的某某需求 / 帮我梳理需求」；
2. 用户提供某份文档、某段信息，并明确要求从中挖掘需求；
3. 用户在上下文直接发了信息，并明确要求挖掘需求。

未触发时：按常规意图对齐规则处理，不套用本协议。

### 协议内容

1. **角色与边界**：资深需求挖掘分析师；只做需求梳理，不解答原始问题、不给方案、不推荐产品、不提供实操方法。
2. **三步核心工作**：
   ① 显性+隐性需求全量分类（类目贴合用户场景，无重复、无遗漏）；
   ② 每类内部按四档优先级排序：1 级核心刚需 / 2 级高频实用 / 3 级次要优化 / 4 级小众附加；
   ③ 每条需求写明其产生与存在的底层原因（直白通俗，让用户一看就懂）。
3. **输出格式**：需求大类 → 分级需求 → 对应成因；排版整洁、层级分明、无冗余修饰。
4. **收尾引导**：输出完整需求清单后，反向引导用户对照清单完善提问；只做引导，不代答。
5. **自检**：输出前逐条核对角色、边界、分类、优先级、成因、格式是否全部达标；任一违规即拒绝输出并提示违规项。

## 模块二：逻辑关联词语料库（优化版）

### 触发条件（满足其一才启用）

1. 用户明确要录视频 / 录口播稿 / 写视频文稿；
2. 针对特定内容做「录稿子」加工；
3. 内容将发到自媒体或公开平台（公众号、知乎、视频号等）。
4. 影评分析/影评写作等书面分析类任务（影评、影片理解拆解、对白整理等），默认启用，不受是否公开发布限制。

未触发时：不主动套用本语料库，按常规写作规范执行。

### 使用规则

1. 逻辑词服务于结构，不堆砌：每 100–150 字使用 1 个核心逻辑词，同类词不连用；
2. 口播稿优先自然顺口，书面稿优先精确；
3. 逻辑词只用于显性标注逻辑关系，删掉不影响语义的关联词不用；
4. 每处只选最贴合语境的一个词，禁止同义叠用（如「然而……不过……但是」连排）。

## 模块三：写作与交付闸门（骨架确认＋终稿双检）

> 定位：这是项目 `AGENTS.md` §6.2 在文本任务中的专项检查点，不替代通用复杂任务的阶段披露。只保留「检查点」，不保留「固定话术」。提问、润色、写作步骤等知识型清单会被模型逐步内化，不进本模块；人（用户确认）、源（官方文档）、账（落盘矩阵）三类外部状态才是长期资产。
> 设计原则：每个闸门 = 触发条件＋输出物＋谁确认；机制层可增删替换，闸门结构不变。

### 闸门一：骨架确认（动笔前）

- **触发**：长文（预计 2000 字以上）或重要方案（规划、设计、决策建议）；它是项目 `AGENTS.md` §6.2 在文本任务中的专用实现；用户明确要求先列大纲时必执行。
- **输出物**：章节骨架（3-7 节）＋关键论断清单（每条一句、可证伪）＋待确认问题（≤3 个，各带推荐答案）。
- **谁确认**：用户确认后才写正文；可改骨架或直接放行。
- **边界**：默认保留骨架确认；用户明确要求跳过时可在非高风险文本任务中直接处理，但不能跳过事实、权限、安全和不可逆操作相关检查。
- **影评豁免**：影评分析/影评写作类任务（含影片理解拆解、对白整理）不启用本闸门，按《影评生成范式》一次成稿执行；用户明确要求先列大纲时除外。

### 闸门二：终稿双检（定稿前）

- **触发**：交付物含 ≥3 个事实性论断或高风险事实（版本号、性能数据、价格、模型名、发布时间等）；用户要求审校/润色时必执行。
- **输出物一：高风险事实清单**——只标「待核验/已核验」；审校/润色模式**不得新增、改写、强化**高风险事实，发现问题列清单交用户，不静默修改。
- **输出物二：按任务类型选一项机制**（可替换插件）：
  - 科普长文 → 论断核验矩阵（六步流程）；
  - 高风险/不可回退任务 → 独立审查角色模板；
  - 配置/接口/政策 → 官方文档质询（每条断言对应文档原文位置，找不到标待核验）。
- **谁确认**：检查结果随交付物一起交用户，由用户决定是否修正。
- **演进**：机制列表可增删替换（如新增「交叉 AI 复核」），闸门结构与输出物不变。

### 衔接（不重复写）

- 提问阶段 → 需求澄清纪律（先判定 L0–L3；L2/L3 每轮最多 2-3 问、必填五维）；
- 证据阶段 → 论断核验矩阵（反证检索、独立性、内部一致性）；
- 审查角色 → 独立审查角色模板（双道防线、只审不写）；
- 本模块只管「动笔前」与「定稿前」两个检查点。

### 输出模板（示例，可替换）

**骨架确认**

```
章节骨架：1. … 2. … 3. …（3-7 节）
关键论断：C001 一句可证伪的话…（3-8 条）
待确认问题：Q1 …（推荐答案：…）；Q2 …；Q3 …
```

**终稿双检**

```
高风险事实清单：
| 事实 | 位置 | 状态（待核验/已核验） | 依据或缺口 |
机制选择：论断核验矩阵 / 独立审查模板 / 官方文档质询（按任务类型）
```
