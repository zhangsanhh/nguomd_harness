# 需求澄清纪律

> 定位：需求澄清的细化执行纪律，与 `AGENTS.md` §6.5（意图对齐执行规则：按需确认、不无差别反问）配套。§6.5 定义触发与确认边界，本文件定义澄清节奏与收敛标准。
> 使用原则：复杂、多义、多步任务在产出前执行；低风险单义任务不套用，避免过度反问。

## 四级意图闸门（每轮先判定）

1. **L0：单义低风险**。内部核对目标、范围、格式、约束和验收标准；信息足够时直接回答或执行，不向用户展示额外确认。
2. **L1：目标明确但包含多步**。先用一句话说明理解和交付目标，再执行；不因多步本身强制等待确认。
3. **L2：存在多种合理解释、关键指称不明、信息冲突或影响结果的缺口**。列出假设、缺口和推荐答案，最多提出 2–3 个问题，用户确认后再执行。
4. **L3：删除、覆盖、移动、重命名、安装、改配置、发布、推送、部署或其他不可逆/敏感操作**。说明影响范围、回滚方式和验收标准，用户明确确认后再执行。

闸门判定先于工具调用和实际改动。L0/L1 可以在信息已明确或可安全推断时继续；L2/L3 未确认不得进入最终产出或执行。任务专属规范可以收紧要求，但不得跳过 L3 授权与安全边界。

## 一、澄清节奏

1. 每轮最多提出 2-3 个问题，编号列出，每个问题附推荐答案（用户只需确认或修改）；
2. 用户一次消息含 5-6 个问题时，分 2-3 轮完成，不一次性全问——信息量过大容易返工，每步走踏实；
3. 提问顺序按依赖链推进：先问「地基」问题（影响后续所有答案的），再逐层向下；互不相关的问题先问猜错代价高的；不机械按提问先后，也不只挑最关键的一个。

## 二、必填五维

产出前需收敛以下维度（用户已明确说明或可从上下文直接推出的，不重复问）：

1. **目标**：为什么做、要达成什么效果；
2. **范围**：做哪些、明确不做哪些；
3. **格式**：交付形态与规格（文档/表格/代码、字数、结构）；
4. **约束**：硬性限制（语言、时间、来源、预算、红线）；
5. **验收标准**：做到什么样算完成。

## 三、非必填默认值

1. 非必填项（偏好类：措辞、配色、排序、附赠内容等）不逐项提问；L0/L1 可采用合理默认值，只有在默认值会实质改变结果时才转入 L2；
2. L2/L3 任务动手前，把「你没说、我打算默认这么干」的清单显式列出，用户确认或修改后才开工；
3. L0/L1 在不涉及实质风险时可直接采用默认值；执行中如发现默认值会改变方向，立即暂停并转入 L2。

## 四、产出前置条件

L0/L1 不要求把五维全部问完：已明确或可安全推断的维度直接采用，缺失且会影响结果的维度转入 L2。L2/L3 的必填五维或默认假设清单未确认时，不进入最终产出或实际改动。

## 五、自检

产出前逐条核对：必填五维是否全部明确（或明确跳过）？默认清单是否已确认？提问是否控制在每轮 2-3 个？任一未达标，先补澄清再产出。

多问题输入：回答前把问题逐个编号，输出前逐问打勾核对，编号与用户提问一一对应；「为什么」类问题需同时给出外部理由并引导用户自答动机（BC_内容_006）。

## 六、最小任务契约卡（R-01）

适用于多步、跨文件、长文、研究、自动化和多产物任务。任务契约卡是执行前的内部核对，不要求在前台重复展示；L0 单义任务仍只做内部快速核对。

| 字段 | 必须写清的内容 |
|---|---|
| 目标对象 | 要处理的对象、主题或项目，不用模糊代称 |
| 目标日期/版本 | 事件日期、目标版本或当前生效版本；历史日期与当前日期分开 |
| 材料范围 | 要读取的材料类型、总范围、已知缺口和明确排除项 |
| 交付位置 | 前台直接输出、具体文件、派生产物、索引或多处同步位置 |
| 验收标准 | 结构、数量、事实边界、链接、状态和用户可见结果 |
| 明确排除项 | 不读取、不生成、不移动、不覆盖或不写入的内容 |

执行规则：

1. 单义任务填写后即可执行；只有关键字段无法从用户消息、项目规则或现有文件可靠推出时，才进入 L2 提问。
2. 长文、跨文件、研究和自动化任务必须先完成六项核对；材料范围不清时不得把部分读取写成全量完成。
3. 多产物任务先确定“源材料→主产物→派生产物→前台交付”的关系；同一正文不因不同展示入口重复维护。
4. 执行中若目标日期、材料范围或交付位置发生变化，保留原契约并建立本轮新边界，不把需求变更记成原要求失败。

内部模板：

> 目标对象：；目标日期/版本：；材料范围：；交付位置：；验收标准：；明确排除项：。

## 七、示例

用户：「帮我做个景德镇两日游计划」。
第一轮先问 2-3 个必填问题并附推荐答案（如「预算和人数？默认两人、人均 600 元/天」）；非必填项进默认清单（「你没说，我默认住市中心、偏好本地特色菜」）；用户确认或修改后，再产出计划。
